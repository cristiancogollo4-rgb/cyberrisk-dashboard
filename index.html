Cadena de explotación

  • 1 · Foothold previo a la autenticación
    Un POST multipart/form-data a /index.php con el campo PHP_SESSION_UPLOAD_PROGRESS alcanza el código de parseo del cuerpo, que corre antes que cualquier script de la aplicación. No hace falta login, ni subida que la app acepte, ni lógica de aplicación.
  • 2 · Fuga de memoria y derrota de ASLRCVE-2026-109618
    Un agotamiento de memoria (bailout con longjmp) deja un puntero colgando (CWE-824). La siguiente petición reocupa ese espacio y PHP devuelve memoria del worker en la cabecera Set-Cookie: PHPSESSID (hasta ~67 KB por petición). El exploit lo hace dos veces: heap base 0x7dad44400000 y libphp base 0x7dad460b1000.
  • 3 · Ejecución remota de códigoCVE-2026-109619
    Se reocupa la referencia colgante con un HashTable forjado cuyo pDestructor apunta a system() dentro de libphp. Al limpiar el valor, el motor llama a system() con bytes del atacante y ejecuta como www-data (HTDATA=0x7dad444690d8 ZIF=0x7dad46516370).
  • Resultado · lectura de la flag
    python3 exploit.py -u http://127.0.0.1:8088/index.php -c 'cat /f>/out/p1' --proof-file out/p1

Mitigaciones y detección

La única corrección completa es parchear el runtime PHP (8.4.27+/8.5.12/8.3.36/8.2.35) y reiniciar todos los workers. Actualizar WordPress, Laravel o el CMS no sirve: el fallo está debajo. Un WAF como módulo de PHP tampoco, porque el daño ocurre antes de que corra la aplicación.
TipoMedidaRiesgo
PrevenciónActualizar PHP a 8.4.27+ y reiniciar todos los workers (fix completo)R-06, R-07
Prevenciónsession.upload_progress.enabled = 0 + reiniciar workers (quita el disparador)R-06, R-08
Prevenciónopcache.enable = 0 (frustra la ruta de ejecución) y, en PHP 8.5, fatal_error_backtraces = 0R-06
PrevenciónRechazar multipart/form-data en el borde (rompe subidas legítimas); mínimo privilegio del proceso PHPR-06, R-08
